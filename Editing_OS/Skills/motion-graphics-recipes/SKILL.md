## Shared production rules

- Derive the brief from supplied footage, product evidence, current references,
  audience and delivery facts. Use actual rational FPS and dimensions. Keep one
  untouched source and author in the existing the selected external job workspace workspace.
- Write scene intentions in `editorial-intent/v1`, using existing semantic roles
  rather than creating new enums for these recipe names. Show the viewer's
  entering question, proof, change and exit understanding.
- Speech reveals use corrected forced alignment and approved post-cut
  `retimed_words`. A cue-level SRT/VTT, raw ASR, character count or beat grid
  cannot supply production word timing. Music-only accents use the placed
  audio clock. Any cut/voice/music-placement change invalidates affected mappings.
- When appearance is unresolved, show 2–3 directions on the same real excerpt,
  including a dense frame and transition. Freeze the explicit choice in the
  existing `taste-selection/v1`; reuse applicable authorized project decisions.
  Morphs, springs, camera moves, blur, typography, palette and sound are choices,
  not mandatory house styling. Keep a valid no-graphic/no-SFX option.
- Keep content and rights traceable: source ID, local path, SHA-256, rights,
  intended use and scene IDs for each asset. Illustration is distinct from
  evidence. Do not fabricate UI behavior, quantities, percentages, testimonials,
  integrations or destinations. A code license does not license every asset.
- Keep extra cue/matte/timing information in one readable job decision artifact,
  linked and hashed from supported contract references/evidence. Existing
  schemas reject unknown properties: do not inject recipe fields into them or
  invent an adapter capability. Use actual schema and engine interfaces.

## Native runtime and final review

For reference identity, physical object motion, material/shader reveals,
imported clip/morph animation or shared website scenes, load the expanded
[studio 3D skill](<../studio-3d-objects/SKILL.md>). Keep this recipe's semantic
anchors and explanatory holds; deeper 3D is not a reason to hide proof, shorten
reading time or introduce another clock. Website/optimizer runtimes remain
conditional on verified local availability.

When a B-roll/product scene needs a closer reference identity, load
[procedural motion design](<../procedural-motion-design/SKILL.md>) for measured
composition, material/type/light rules and coherent motion. Use the existing
[Studio Objects 3D](<../studio-3d-objects/SKILL.md>) route for a real-looking object
that opens, stacks, stamps or refracts; an isometric drawing is a different look.

Use the actual installed HyperFrames contract: finite composition root and
timed clips/media, one paused registered timeline per composition, local fonts
and assets, framework-owned media playback. Do not substitute upstream
`window.seek`, an autoplay clock, CSS transitions or a custom audio scheduler
for framework seeking. Analytic or baked camera paths must reproduce the same
state after forward, backward and repeated seeks. Avoid render-time randomness
and network loads. Do not upgrade a project's pinned renderer during production
without checking the existing project's compatibility workflow.

Review entrance, semantic activation/contact, transition midpoint, settled hold,
exit, densest frame and both endpoints. Holds need reading/recognition time
after motion settles. Check phone-scale type, captions, proof and subject
clearance; blur must not erase the information being demonstrated. A handoff
records integer in/out frames with exclusive ends, rational FPS, duration,
source/output mapping, alpha convention when applicable and what is illustrative.
Rendered overlays are editable assets in the finishing workflow, not a claim
of native editable CapCut project transfer.

Capture actual graphics, applicable captions and audio QA in existing evidence
envelopes. Bespoke scenes require bespoke review; the generic graphics planner
does not validate every UI/camera/matte technique. The encoded artifact still
needs full Quality Engine checks, independent repeat rendering or its declared
waiver, and exact-hash human playback/device review. Only Quality readiness and
adapter publication authorization permit a publication-ready claim.

Changed Tool Routing hashes require live preflight and refresh/reapproval of
affected contracts when resuming jobs; never rewrite prior approvals to match.
See the [public source and scope notes](../PROVENANCE.md)
for source coverage, rejected defaults, verification and capability limits.
