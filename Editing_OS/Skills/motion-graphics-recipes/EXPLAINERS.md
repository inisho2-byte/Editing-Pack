# Product explainer construction

Read with [SKILL.md](<SKILL.md>). These are three narrative tools; duration,
energy and branding come from the actual brief. Product films retain the
product-launch/custom-video route. They do not become a standalone short-motion
job merely because the visuals are animated.

## Choose the explanation mechanism

| Mode | Viewer needs | Narrative construction | Main risk |
|---|---|---|---|
| Demonstration | See what a real action produces | Relevant problem/input → action → inspectable result → payoff | A beautiful reconstructed UI implies unsupported behavior |
| Continuous journey | Understand what passes through a workflow | One identifiable object visits ordered stations → result → overview | The camera or metaphor hides causality/order |
| Kinetic promo | Remember a concise value proposition | Earned hook → a few claim/proof beats → signature idea → readable ending | Speed, decorations and music erase the message |

Use existing scene roles (`proof_demonstration`, `mechanism_explanation`,
`contrast_transformation`, `payoff`, etc.) in the editorial contract. These
mode names are recipe labels, not schema values.

Verify product features, labels, outcomes, integration names and CTA against
supplied evidence/current authoritative product material. A diagram inspired by
a site is illustrative. A polished reconstructed interface is not screen-recorded
proof. Keep a source screenshot/capture and version/date for reconstruction;
label mockups and sample data. Prefer real capture where exact behavior matters.
Do not hide errors, waiting time or qualifying copy to imply a false capability.

## Demonstration: action and result

Begin with the relevant question or result when useful; an obligatory
"Introducing" scene consumes attention without necessarily giving value.
Build chapters around concrete tasks. Orient the viewer, move close to the
control, show action, hold the result, then recover context before the next task.

Camera movement should reveal detail or reconnect context. Compute framing from
actual transformed bounds, including cursor, result and longest label. Avoid
following every typed character if it makes the content unstable. Text can wrap
and reflow deliberately; do not globally force nowrap. Size type for the final
device rather than copying web UI pixel sizes. Reduce chapter count when the
requested duration cannot fit readable results; do not compress every hold.

Each chapter needs input, actual action, truthful result and a failure condition.
Claims with quantities need units/source; illustrative progress must not imply
benchmarked speed. Show integrations once with honest labels rather than
duplicating tiles to suggest a larger supported ecosystem. Blank/skeleton bars
can also imply data: label illustration and avoid a quantitative scale.

## Continuous journey: one object, stable geography

Choose an object native to the workflow: a request, file, message or record.
Keep recognizable identity as its state changes. Place each station according
to actual process order on a stable world layout. Every visit must cause a
visible, correctly labeled state change; remove stations that add only motion.

Plan object contact and station response before camera embellishment. Track the
object in world coordinates; derive camera framing and contact points from the
same coordinates. During interaction, frame the station/result; during travel,
lead toward the next destination. At payoff, hold the result before an overview
reveals how the stations connect. If the overview makes labels illegible,
preserve recognition with selective emphasis rather than tiny explanatory copy.

Camera follow must be analytic or pre-baked on a fixed time grid, with specified
initial conditions and interpolation. Do not integrate a spring once per
requested render frame: backward/out-of-order seeking would change the result.
Choose damping and path speed from readability, not assumed physics constants.
An object's playful impact is an optional selected treatment, not evidence of
causal product behavior. Captions remain available if required; a cinematic
one-take constraint cannot ban accessibility text.

Loops are optional and cannot reverse a real irreversible process as if that
were product behavior. A metaphorical reset must read as a loop device. Check
position, velocity, camera, station state, opacity and audio tail across the
seam. Compare the last encoded frame to the first and assess the first step
after wrap; copying endpoint positions alone does not prove a smooth loop.
Keep a finite export duration and declare intentional looping/holds to QA.

## Kinetic promo: controlled energy

Choose a small number of defensible claims and one distinctive visual metaphor.
Carry an object/shape across a transition only when it connects meaning or
directs attention. Establish carry-out/carry-in position, size, direction and
color continuity; keep one focal event per beat. Alternate impact with readable
settled holds so the payoff registers. A still hold is legitimate motion design.

Use a verified grid from the placed music only for flexible accent timing.
Speech and reading load govern narrated scenes. Do not force all reveals onto
subdivisions, add a HUD/timecode, spin objects or add saturated fills because
the upstream style did so. UI chrome, grain, depth and blur must earn their
place in the selected treatment; check phone legibility and flashing risk.
Review the shortest text exposure and transition peak, not only hero stills.

## Build and review

Use native HyperFrames scene/subcomposition structure and the installed
animation adapter. Local fonts require verified load/glyph coverage; brand
assets require the job rights ledger. Keep audio framework-owned and follow
[SOUND_DESIGN.md](<SOUND_DESIGN.md>) when a mix is requested. Neither synthetic
music nor a sound library is an implicit part of this integration.

Before a long render, review a complete representative interaction, longest
copy, densest scene, camera extrema, journey overview or carried transition,
and end card. Seek these times in both directions. Record placeholder content
and unresolved decisions plainly. Deliver editable composition, approved assets,
review copy and decision/evidence links through the existing storage-light
workflow. A rendered demo still requires the existing exact-artifact release gate.
