# Audio-reactive motion inside Editing OS

This is an owned adaptation of ACE-Step's `acestep-simplemv` ideas, inspected
remotely at commit `ca1e85fe9430179831e6bc6be790c332190a3866` on 2026-10-12.
No upstream repository, scripts, models or dependencies were installed. This
skill does not generate music or install ACE-Step/Remotion.

Load [Master Prompt](<../MASTER_PROMPT.md>), [Taste Profile](<../TASTE_PROFILE.md>),
[Tool Routing](<../TOOL_ROUTING.md>) and [Quality Standard](<../QUALITY_STANDARD.md>)
first. Use the existing production-context, editorial-intent, taste-selection
and applicable audio-plan contracts and the owned Orchestration Adapter. This
workflow is a specialist recipe, never a competing approval or release gate.

The routing update changes a governing-document hash. On resuming an existing
job, run the adapter's live-hash preflight and refresh/reapprove affected
contracts through the existing workflow; do not edit old approvals to appear valid.

## Route the requested result

| Request | Route and decision |
|---|---|
| Spectrum/music visualizer | This skill → owned offline audio analysis → bespoke HyperFrames composition |
| Audio-reactive title or accent | This skill for measured energy; existing selected graphics treatment for layout/type |
| Lyric video | This skill for scene/layout; existing WhisperX + Captions engine for verified sung-word timing |
| Beat-cut montage or full music-led film | Available HyperFrames `music-to-video` workflow for planning; this recipe only where audio-reactive scenes help |
| Talking-head explanation | Existing Graphics engine + `retimed_words`; music reaction must not replace spoken semantic anchors |
| New song, cover, stem separation or repaint | Separate music-generation job; ACE-Step runtime is unavailable through this integration |

Never install a missing vendor dependency to make this recipe work. Use the
existing local renderer/runtime, or report the concrete missing capability.
Read [IMPLEMENTATION.md](<IMPLEMENTATION.md>) when building/analyzing a scene.

## Decide the scene before reacting to audio

Establish the licensed source track, actual delivery geometry/FPS, language,
audience, intended emotion, section progression and required lyrics. Keep the
original track immutable. Author in the existing the selected external job workspace workspace.
Record every background, audio track and font in the job's asset ledger with
source/rights, purpose, local path and SHA-256. A repository software license
does not establish music, voice, likeness or image rights.

Choose a viewer task: feel a musical change, follow lyrics, identify a song, or
understand audio evidence. Do not imply a decorative spectrum is calibrated
measurement. Use one focal layer; title, lyric and visualizer each have a role.

When appearance is unresolved, show 2–3 useful treatments on the **same real
excerpt**, including a dense lyric/peak and a transition. Useful proposals:

- restrained single-accent spectrum beneath a stable title;
- lyric-first composition with small energy-driven accents;
- image-led composition with subtle measured energy and clear type.

These are options, not authorized defaults. Freeze the human's explicit choice
in `taste-selection/v1`, including palette, typography, safe area, bar count,
motion gain, smoothing and background treatment. Reuse a prior explicitly
authorized look when it applies. The Taste Profile remains unchanged by this
OS upgrade. Remove rainbow cycling, heavy glow or pulsing text unless chosen
on actual material and still readable.

## Preserve the two timing responsibilities

**Music reaction** uses analyzed samples on the final music-placement clock.
**Words** use corrected forced alignment and, after cuts, approved
`retimed_words`. Beats do not decide word activation or explanatory reveals.
If music is trimmed, moved, stretched, looped or mixed differently, regenerate
the analysis for the actual placed segment, or document the exact source-time
mapping and offsets. Do not analyze one track while playing another.

LRC and ASR are candidate lyric inputs. Listen against authoritative lyrics,
check names and repeated sections, then verify sung onsets and offsets. Do not
retain incorrect timestamps merely because wording was corrected. Do not split
line timestamps evenly into words, add a fixed -0.5s offset, or invent a final
line duration. If singing defeats forced alignment, resolve the alignment and
review evidence before production timed lyrics; a draft or static lyric card
must be labeled accurately. A manually edited file alone is not alignment
provenance.

## Build and verify

Use the installed HyperFrames core/animation contract: one paused, registered
timeline, finite duration, local assets/fonts and framework-owned audio. Measure
energy/spectrum offline; visual state must be reproducible at any requested
time, including backwards seeks. No live WebAudio analyser, CSS transitions,
autoplay timer, network asset or render-time random motion.

Keep text stable while the spectrum moves. Allocate clearance for peak bar
height and any title motion; design portrait/landscape independently from the
actual delivery context. Background art must leave space for lyrics; text that
must remain editable belongs in the composition. Typography baked into an
image follows the owned Ideogram route and its existing cost gate.

Before a long render, check silence, a quiet passage, a peak, section changes,
longest lyric, final lyric, first/last frames and peak layout density. Review
forward/backward seeking at the same frame, glyph coverage, phone-scale text,
no clipping/overlap, real spectrum response and clean head/tail audio. Frame
analysis is not beat detection, forced alignment, loudness QA or graphics QA.

Use actual HyperFrames lint/check and capture their logs; bespoke scenes need
real graphics QA rather than the generic planner's seven-family coverage claim.
Record applicable caption and audio QA through the existing evidence envelopes.
Run encoded-artifact Quality Engine checks, the declared independent repeat
render or explicit scoped waiver, and exact-hash human playback/device review.
Re-encoding for a size limit creates a new artifact requiring new hash-bound
QA/review. Only Quality Engine readiness plus adapter publication authorization
permits a publication-ready claim.
