# Start here

For first-time setup, follow [getting started](../../docs/getting-started.md). For an editing job, read the toolkit root [AGENTS.md](../../AGENTS.md). Load MASTER_PROMPT.md, TASTE_PROFILE.md, TOOL_ROUTING.md, QUALITY_STANDARD.md and [the handbook](<Video editing handbook/Elite_AI_Video_Editing_Workflow.md>) before an editing job. Keep all job inputs, decisions and evidence in an explicitly selected external workspace.

1. Define the objective, audience, authorized sources, references and delivery/review requirements; validate production context against the five current document hashes.
2. Inspect source facts and obtain genuine forced-aligned words; raw ASR and synthetic examples do not qualify.
3. Plan editorial intent and scenes, propose a word-safe EDL, then obtain explicit hash-bound timing approval through the owned adapter.
4. Show treatment options on actual material where unresolved and record explicit taste-selection/v1. Use the one retimed post-cut clock for captions and graphics.
5. Build only with consumed adapter authority and selected treatment; keep media assets' rights/provenance with the job.
6. For an editable handoff, verify the intended new/empty native project and independent clip readback. App bridges are conditional; an MP4 is a flat review artifact.
7. Verify the exact encoded export, required repeat/waiver and component evidence with Quality_engine. Obtain artifact-bound human review before adapter publication authorization.

The owned workbench is at Editing_OS/Tools/editing-workbench; from this file use [its guide](../Tools/editing-workbench/GUIDE.md). Scene guidance is in [SCENE_PATTERNS.md](SCENE_PATTERNS.md). Use [installation](../../docs/installation.md) and [configuration](../../docs/configuration.md) for the tested standalone Windows setup. Example approvals never authorize a real job.

See [architecture](../../docs/architecture.md), [workflow](../../docs/workflow.md) and [capabilities](../../docs/capabilities.md) for public entry points and limits.
